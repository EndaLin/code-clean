# Go 函数、方法、类型与接口

## 函数与控制流

- `[Go]` 用 Go 的类型、错误返回、接口和组合表达设计，不把 Java 或 C++ 的类层次逐字翻译过来。
- `[Go]` 多返回值用于同时返回结果和状态，`error` 通常放在最后。命名返回值只在能澄清含义或确需由 `defer` 修改时使用；裸 `return` 只适合一眼可读的短函数。
- `[Go]` `defer` 紧跟成功取得资源、锁或清理责任之后，使所有退出路径可见。确认被延迟调用的参数求值时机，并按 API 契约处理 `Close`、`Flush` 等操作本身的错误。
- `[融合]` 初始化语句配合 `if` 或 `switch` 可缩小变量作用域；失败分支已经返回后通常省略 `else`。不要为了少几行把多个独立副作用塞进条件表达式。
- `[Go]` 避免在 `init` 中执行网络、文件、进程退出或难以测试的全局初始化。优先显式构造和启动流程；确需注册型副作用时保持局部且可追踪。

## 数据与零值

- `[Go]` 尽量让类型的零值可直接使用；若零值无效或语义不显然，在构造入口和文档中说明并强制建立不变量。
- `[Go]` `make` 初始化 slice、map 和 channel 的底层状态；`new` 只分配零值。nil slice 通常可安全读取和追加，nil map 可读但不可写；是否返回 nil slice 或空 slice 取决于 JSON、RPC 等边界契约。
- `[Go]` `append` 可能更换底层数组，必须使用其返回值。切片可能共享存储；跨边界保存、并发使用或缩容时，明确所有权并在需要时复制。
- `[Go]` 不依赖 map 遍历顺序。跨包或跨长期维护边界构造结构体时优先带字段名的复合字面量，避免新增字段后静默错位。
- `[Go]` 不为了省几个字节传递 `*string` 或接口指针。使用指针应表达可变性、共享身份、可空语义或避免复制确实较大的值。

## 方法、接口与组合

- `[Go]` 值接收者适合小型、不可变且可安全复制的值；指针接收者适合修改状态、保持身份、避免大对象复制或包含不可复制成员的类型。同一类型的方法集保持一致，除非差异有清楚理由。
- `[Go]` 不复制包含 `sync.Mutex`、`sync.Once`、原子值或其他声明为不可复制成员的结构体；方法通常使用指针接收者。
- `[Go]` 接口保持小而聚焦，通常由使用方按所需行为定义。默认接受必要的最小接口、返回具体类型；若调用者确实依赖稳定抽象，返回接口也可以。
- `[Go]` 接口是方法集合，不需要显式声明实现。编译期接口断言只在实现关系不会被其他静态用法自然检查、且该关系值得明确时添加。
- `[Go]` 内嵌是组合和方法提升，不是继承。确认提升后的公开方法集、同名冲突、nil 内嵌指针和外部类型升级带来的影响；仅为少写转发代码而内嵌通常不够。
- `[Go]` 命名函数类型可以作为轻量适配器实现接口，但要保证转换后的行为和 nil 语义清楚。

## 泛型

- `[Go]` 泛型用于多个类型共享同一真实操作和约束的场景。若一个具体类型或小接口更清楚，不用 `any` 和类型参数制造抽象。
- `[Go]` 约束表达算法实际需要的能力，并考虑类型推断、零值、可比较性和 API 演进。旧版《Effective Go》不覆盖泛型，必须按项目声明的 Go 版本和现行官方文档判断。
