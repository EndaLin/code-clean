# Go 并发

## 生命周期先于语法

- `[Go]` 每个新 goroutine 都要能回答：谁启动、何时退出、如何取消、谁等待、错误交给谁。没有退出路径或无人观察结果的 goroutine 很可能泄漏。
- `[Go]` 请求范围的取消、截止时间和元数据通过 `context.Context` 传递。通常把 `ctx` 放在第一个参数，默认不存入结构体、不传 nil，并调用派生 context 的取消函数释放资源。受既有接口签名限制等少数例外，应明确 context 的生命周期。
- `[Go]` goroutine 中的 panic 不能由其他 goroutine 的 `recover` 捕获。需要隔离时在被启动的 goroutine 自己的边界处理，并保留失败信号。
- `[Go]` 限制并发应在创建工作前建立容量或使用固定 worker；不要先无限创建 goroutine，再让它们全部堵在内部信号量上。

## channel、锁与所有权

- `[融合]` channel 适合传递所有权、事件和流水线；mutex 或原子操作适合保护简单共享状态。选择让不变量和生命周期最清楚的工具，不把“通过通信共享”解释成禁止锁。
- `[Go]` 由发送方或拥有发送生命周期的一方关闭 channel；接收方通常不关闭，且 channel 不必总被关闭。重复关闭、向已关闭 channel 发送都会 panic。
- `[Go]` API 参数尽量使用方向明确的 `<-chan T` 或 `chan<- T`。缓冲大小是背压和阻塞语义的一部分，不是随意的性能旋钮；nil channel 会永久阻塞收发。
- `[Go]` 接收方可能提前退出的流水线必须通知上游停止发送，通常使用 context 或关闭只用于广播取消的 channel。所有退出路径都要释放 worker 并完成等待计数。
- `[Go]` 共享变量的每次访问都遵守同一把锁、原子协议或单一 goroutine 所有权。普通 map 不能在未同步的并发读写中使用。
- `[Go]` 不复制已经使用的 `sync.Mutex`、`sync.Once`、`sync.WaitGroup` 等同步值。锁的保护范围和字段归属在结构上或注释中保持清楚。

## 闭包、循环和验证

- `[Go]` 启动 goroutine 时显式审视闭包捕获值、指针别名和共享状态。模块声明 Go 1.22 及以上时，循环声明变量具有每次迭代独立的语义；旧模块仍需按旧语义处理，不能机械添加或删除 `x := x`。
- `[Go]` 并发测试避免靠固定 `sleep` 猜测完成时序；使用 channel、等待组、条件或可控时钟建立可观察同步。
- `[Go]` 运行覆盖相关路径的 `go test -race`。竞态检测只能发现实际执行到的竞争，未覆盖路径仍需通过所有权分析、压力测试和真实负载验证。
- `[Go]` 对外类型若支持多 goroutine 并发使用，在文档中明确保证；没有声明时不要让调用者猜测哪些方法可并发调用。
