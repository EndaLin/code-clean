# Java 数据库、安全与工程边界

仅在任务触及 SQL、ORM、接口安全、依赖或部署边界时读取本文件。许多规则属于组织架构选择，不应脱离现有系统机械执行。

## 数据库与 ORM

- `[强]` SQL 使用参数绑定，不拼接用户输入；MyBatis 使用 `#{}` 绑定值，`${}` 只允许经过严格白名单控制的结构标识符。
- `[强]` 查询明确列名，不使用 `SELECT *`；多表查询给列加清楚的表别名，避免字段冲突和无意扩大数据契约。
- `[强]` 理解 `COUNT(*)`、`COUNT(column)`、`SUM` 与 `NULL` 的差异；分页总数为零时避免无意义的数据查询。
- `[强]` 数据变更同步维护审计时间或版本字段，前提是项目 schema 具有该契约。
- `[融合]` 数据对象字段类型、可空性、布尔映射和精度必须与 schema 一致；不要让 JavaBeans 命名与 `is_xxx` 数据库字段产生隐式错配。
- `[融合]` 唯一业务约束优先由数据库唯一约束保障，并在应用层提供清楚错误；索引依据查询计划、数据分布和写入成本设计。
- `[建议]` 深分页、模糊搜索、多表关联和大批量 `IN` 需要基于真实执行计划与数据量评估，不把固定阈值当普遍定律。
- `[融合]` 外键、逻辑删除、存储过程、分库分表和冗余字段是系统级决策。黄山版的绝对取舍只作为风险清单，不能覆盖已有一致性模型。
- `[强]` 数据修正或删除先缩小范围并核对目标，使用事务、备份或可恢复方案；这类操作需要单独授权。

## 安全

- `[强]` 对用户资源同时验证身份和对象级权限，不能只隐藏页面入口。
- `[强]` 所有外部输入验证类型、范围、长度、数量和允许值；验证不能替代输出编码或参数绑定。
- `[强]` HTML、脚本、SQL、路径、命令和重定向分别使用对应上下文的安全编码或白名单，避免注入与开放重定向。
- `[强]` 状态变更请求采用项目框架提供的 CSRF、防重放、幂等和频率限制机制。
- `[强]` 文件上传限制大小、类型、内容、名称和存储位置；不要信任客户端 MIME 或扩展名。
- `[强]` 密码、令牌和私钥不得写入源码、普通配置或日志，使用密钥管理系统并支持轮换。
- `[强]` 展示、日志和导出中的个人敏感数据按最小必要原则脱敏。

## 接口与依赖

- `[融合]` API 明确方法、路径、请求和响应 schema、状态码、错误结构、分页、大小限制、时区及缓存语义。
- `[强]` 超大整数跨 JavaScript 边界时使用不会丢失精度的字符串或明确 schema 类型。
- `[强]` 所有远程调用设置连接、请求和总体超时，并定义重试、幂等、取消和降级策略。
- `[融合]` 依赖版本集中管理并保持收敛；生产版本避免不稳定快照。升级时检查传递依赖、许可证和行为兼容性。
- `[原则]` 第三方库放在适配边界，用小型集成测试验证真实行为，避免其类型和异常渗透整个领域层。

## 架构

- `[原则]` 分层的目的在于明确职责和依赖方向，不是增加固定层数。跨层捷径只有在不破坏契约时才合理。
- `[融合]` 识别弱依赖和失败模式，为核心路径设置超时、隔离、降级和可观测性；不要在没有业务语义时吞错返回空值。
- `[原则]` 状态图、时序图、类图和活动图只在能降低复杂交互的理解成本时使用，不按对象数量强制绘制。
- `[原则]` 设计文档记录需求、边界、难点和关键取舍；清晰代码是文档的一部分，但不能替代协议和系统决策记录。
