# Java 语言、类型与数据

## 类型与对象契约

- `[强]` 覆写方法添加 `@Override`；静态成员通过类名访问。
- `[强]` 覆写 `equals` 时同时覆写 `hashCode`。作为 `Set` 元素或 `Map` 键的自定义值对象必须满足两者契约，并优先保持不可变。
- `[强]` 包装整数比较值使用 `equals` 或显式拆箱，不依赖缓存范围内的引用相等。
- `[强]` 数据对象字段类型与数据库、消息或序列化字段范围一致，避免溢出和精度丢失。
- `[融合]` POJO 字段是否一律使用包装类型取决于“未赋值”是否有业务含义；RPC/JSON 契约也要依据 schema，而不是机械替换全部基本类型。
- `[强]` 兼容序列化类增加字段时保持兼容的 `serialVersionUID`；不兼容变更必须显式升级契约。
- `[融合]` `toString` 应便于诊断且不得泄露敏感数据。记录类、IDE 或生成器可提供实现，但不要递归打印大型对象图。
- `[建议]` 构造器建立有效对象，不执行远程调用或复杂业务流程；复杂创建使用工厂，但无需额外的 `init()` 让对象暂时无效。

## 数值与货币

- `[强]` `long` 字面量使用大写 `L`，`float`/`double` 后缀保持清楚。
- `[强]` 浮点值不直接用 `==` 判断业务等值；使用明确误差范围，或在十进制定点场景使用 `BigDecimal`。
- `[强]` `BigDecimal` 从字符串或 `valueOf` 构造，数值等值通常用 `compareTo`；需要同时比较刻度时才用 `equals`。
- `[融合]` 货币使用明确币种与精度。最小货币单位整数适合固定精度场景；需要可变精度时使用领域金额类型或 `BigDecimal`，不得用二进制浮点数。
- `[强]` 常量按职责和最小共享范围组织，不建一个包揽所有业务的常量类。固定有限状态优先使用枚举或密封类型。

## 日期时间

- `[强]` 日期格式中区分 `yyyy` 与周所属年 `YYYY`、月份 `M` 与分钟 `m`、24 小时 `H` 与 12 小时 `h`。
- `[融合]` 新代码优先 `java.time` 的不可变类型和 `DateTimeFormatter`；不在多线程间共享 `SimpleDateFormat`。
- `[强]` 不把一年写死为 365 天，使用日期类型处理闰年、月底、时区和夏令时边界。
- `[融合]` 业务时间显式携带时区或偏移；测试中注入 `Clock`，不要依赖不可控的当前时间。
- `[融合]` `java.sql.Date/Time/Timestamp` 只允许出现在旧 JDBC 兼容边界，进入领域层后转换为 `java.time` 类型。

## API 与兼容性

- `[强]` 不修改已有调用者依赖的方法签名、字段语义或序列化名称，除非用户明确接受兼容性变更。
- `[强]` 过时 API 的替代方案和迁移路径要清楚；不要继续引入已废弃方法。
- `[融合]` 避免同时生成 `isXxx()` 与 `getXxx()` 等会让框架解析产生歧义的访问器，修改前实际核对所用框架。
- `[建议]` 谨慎使用 `clone`；优先显式复制、复制构造器或不可变值对象。
